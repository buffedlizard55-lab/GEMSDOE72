For executives: what this competition is in 30 seconds

Prize: $300k total ($50k Initial Round + $250k Final Round) to find faults that indicate geothermal resources in NW Nevada (GeoDAWN region). Unique twist: the provided fault map is incomplete — experts have secretly labeled new faults for private test. Your submission helps update the full map. One file is scored in both rounds.

What you submit: One GeoTIFF with per-pixel confidence 0–1 that a fault exists. The organizer scores it with distance-weighted Tversky (α=0.2 FP, β=0.8 FN, 300 m triangular kernel). You have 3 scored submissions per week; only your chosen file counts in both prize rounds.

What this repo gives you: A one-click .tif that is legal, unique, and portal-safe — download, upload to DrivenData, done. No assembly, no command line, no data download required. Plus the science behind it, audited.

Step-by-step: how to submit this file to the contest

  1. Download the file: On the overview page click the green ⬇ ONE-CLICK SUBMISSION (.tif) button. Save gemsdoe72-h72-...-zeros.tif (or the .zip containing it — portal accepts both). Keep the file name unchanged.
  2. Go to the competition submit form: DrivenData competition page → Submit (requires log-in). You will see File to submit — No file chosen.
  3. Attach the file: Click Choose file → select the downloaded .tif (recommended: zeros.tif variant, all cells finite) or .zip. The nan.tif twin is identical inside the footprint but uses NaN outside (sample format) — use it only if a portal quirk demands NaN.
  4. Fill the unique name field: Paste GEMSDOE72-H72-halo-div-42k — this is the submission's unique slug.
  5. Fill the optional note field: Paste GEMSDOE72 H72 halo-div 42k | Th/K Roberts + cond grad + topo divergence, 2px cat buffer, 0 on-cat; HOLDOUT-DTI 0.1554 drift (140 chars). Helps you tell submissions apart.
  6. Create submission → wait for score: Portal validates format first (see error fix below), then queues for scoring. Public leaderboard updates; private test score is revealed only at round close — you pre-select one file for both rounds.

The portal error you hit — and the fix

Symptom: Submitting a .tif returns "Predicted values must be in range [0, 1]" even though inside values look like 0/1.

Root causes (measured):

  • Mechanism 1 — Float32 sentinel: training_features.tif uses nodata -3.4028234663852886e+38 — 7,113,308 cells, 3,061 inside footprint. Writing those through puts them outside [0,1].
  • Mechanism 2 — NaN sentinel + nodata tag: A raster with nodata=NaN and NaN cells outside footprint is legal per problem description, but one validator change away from rejection; plus some writers set nodata to the sentinel.

Fix verified by re-reading bytes: Every GeoTIFF on this site is single-band Float32, EPSG:32611, 100 m, 3730×3292, all 12,279,160 cells finite, min 0.0 max 1.0, zero NaN, no nodata tag for the zeros variant. The nan twin is offered for format fidelity but is one validator change away from the same error. Each download ships a checksum receipt (*-audit.json) produced by re-opening the file from disk (see scripts/audit_shipped.py).

What was verified (and what is not claimed)

  • Metric implementation matches published worked example TP=3.00 FP=1.89 FN=2.00 → DTI 0.60 (pytest).
  • Transform/CRS/shape match sample_submission.tif byte-for-byte (via re-read).
  • sha256 of every shipped raster is published; sidecar *-audit.json is generated after write.
  • Not claimed: No organizer score exists for any artifact in this repository. All DTI numbers are HOLDOUT-DTI (local spatially-blocked holdout, drift-corrected) unless marked ORGANIZER-CONFIRMED.

Budget & lane rule

Stop after 3 experiments or 2 hours. This repo's primary (H72 42k) was validated on blocked holdout before any weekly slot — do not spend a slot on an idea that hasn't beaten the current holdout best. Lane rule: if rank-correlation with any registry raster exceeds 0.90 or >70% dots fall within 3 px of one registry raster, log as duplicate and stop — our emission is 0.38/0.18, so unique.
