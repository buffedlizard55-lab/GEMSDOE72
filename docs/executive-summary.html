What the competition form expects

The official problem page specifies a single-band GeoTIFF with pixel-wise confidence values and requires the training grid's projected CRS (UTM zone 11N, EPSG:32611), 100 m resolution, matching bounds/grid, float32 values in [0,1], and null/NaN outside the submission footprint. The competition data page provides the sample format; access may require a DrivenData login.

When a candidate file has passed the gates

  1. On the landing page, confirm that its status explicitly says SAFE TO DOWNLOAD AND SUBMIT, and open that unique candidate's validation receipt. If the status says unavailable, blocked, negative, or unvalidated, stop.
  2. Download the named .tif file. Do not rename or modify it after its recorded SHA-256 has been verified.
  3. Open the official DrivenData competition and select Submit predictions / New submission.
  4. Use File to submit to select the downloaded GeoTIFF. A ZIP is acceptable only if it contains exactly one GeoTIFF, per the submission form.
  5. Enter the candidate's displayed unique submission name as the competition's submission identifier if requested. Paste the displayed short note into Note (optional); keep it within 140 characters and do not call a holdout estimate an organizer score.
  6. Submit only after your team has selected that candidate under the competition's slot policy. Validation does not authorize consuming a weekly slot.
  7. Save the DrivenData receipt and report its exact organizer score only as ORGANIZER-CONFIRMED copied from that receipt. A public leaderboard listing is a separate evidence source.

Pre-submit validation receipt must confirm

  • single band; float32; CRS EPSG:32611; exact shape, affine transform, and bounds match to the official sample
  • all in-footprint predictions finite and between 0 and 1 inclusive; outside-footprint cells null/NaN; no invalid nodata sentinel inside the footprint
  • the on-disk file was reopened and checked; SHA-256, raster dimensions, transform, bounds, finite count, min/max, and nodata policy recorded
  • candidate is distinct from the registry rasters: rank correlation and dot overlap checks run before placement and after final emission; if either protocol threshold is crossed, mark duplicate and stop
  • method has passed the registered spatial-blocked hide-and-recover holdout, per-feature leakage canaries, and uncertainty reporting; negative results remain documented

The previous portal message “Predicted values must be in range [0, 1]” is not diagnosed for this checkout. Do not assume its cause. Validate the actual written raster, including in-footprint nodata values, before retrying a submission.
