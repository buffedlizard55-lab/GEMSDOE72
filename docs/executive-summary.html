Executive summary — how to make a GEMS Prize submission

DOE GEMS Prize Challenge (DrivenData #306) · submit a single-band GeoTIFF of fault probabilities

● The one thing to do first: download the submission file

Go to the home page. At the very top is a one-click download button for the submission GeoTIFF.

Open home page → Download .zip

The .tif and .zip contain the same single-band float32 GeoTIFF. DrivenData accepts either a single .tif or a .zip containing one .tif.

Step-by-step: submit on DrivenData

1. Log in. Open the DrivenData submissions page and sign in.
2. Choose file. Click "File to submit" and select gemsdoe72-baseline-dotted-budget-20261020T194809Z-5e1a26d8-zeros-outside-footprint.tif (or the .zip).
3. Add a note. In "Note (optional)" paste a short comment so you can tell submissions apart (e.g. the hypothesis / clustering label). Suggested note below.
4. Submit. Click submit. DrivenData checks the format: single-band float32 GeoTIFF, EPSG:32611, 100 m, same bounds/transform as the training data, values in [0, 1].

Known submission error and the fix. DrivenData rejects a raster whose values fall outside [0, 1] or whose nodata tag is a large negative float32 sentinel (-3.4028234663852886e+38, as used in training_features.tif). Both produce the same "Predicted values must be in range [0, 1]" message. This site's file is written all-finite with nodata=None, so neither failure mode applies (verified by re-reading the bytes).
