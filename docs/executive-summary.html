The DrivenData form accepts "a single-band GeoTIFF (.tif) file, or a .zip file containing a single GeoTIFF". The -zeros.tif is the belt-and-braces choice: zero NaN anywhere, so no validator can reject it for out-of-range values.

Step-by-step: how to submit

1. Download. On the landing page click Download submission GeoTIFF (zeros, all-finite, in [0,1]). Save the .tif.
2. Open the submission form. Go to the DrivenData New submission page for the GEMS Prize ("File to submit" → "No file chosen").
3. Upload. Select the single .tif (or a .zip containing only that .tif). It must match the submission format's CRS, shape, and geotransform — this file was written on the pinned sample_submission.tif template.
4. Note. Paste the 137-character note above into "Note (optional)" — it helps you tell submissions apart later (e.g. clustering with k=25).
5. Submit. Wait for the portal to score it; the leaderboard value, if accepted, is the only ORGANIZER-CONFIRMED number.

The [0, 1] error, fixed

DrivenData rejects submissions whose predicted values fall outside [0, 1] — and it rejects the old float32 nodata sentinel -3.4028234663852886e+38 with the same message, because that sentinel is not a value in [0, 1]. This file avoids both failure modes: no NaN anywhere (zeros variant), no sentinel, all values clipped to [0, 1] inside the footprint and exactly 0.0 outside. Verified by an independent re-read of the published bytes (12-point audit, all passed).
